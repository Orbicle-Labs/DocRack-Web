## Implemented behaviour

- Both forms use shared trimmed/lowercased Zod schemas. Original endpoints, fields, four audit-count values, exact Sheets tabs/columns, RAW append and status contracts remain; request guards additionally return 403/413/415. Delayed hydration preserves complete drafts, and submission waits for hydration. Failure retains inputs; first invalid fields and successful receipt headings receive focus. Repeated clicks cannot create concurrent browser submissions. No visitor-email, reservation or response-time promise.
- Origin/JSON guards and a 16 KiB streaming limit apply before parsing; stalled reads cancel after five seconds. Missing-Origin clients require explicit configuration. Arbitrary forwarded headers are ignored. Default shared identity is conservative and can throttle unrelated visitors; precise per-client enforcement requires verified exclusive ingress that overwrites the dedicated header.
- Firestore transactions use separate demo/support HMAC keys, fixed windows (3/20 minutes and 5/30 minutes), counts/reset/expiry and application expiry checks. The bounded map shadows local attempts, prunes expired entries and supports degraded operation with a circuit breaker. Real SDK retry/timeout configuration is tested; mocks model transaction serialisation. No cloud resources, emulator acceptance, TTL policy or global fallback guarantee is claimed.
- Sheets appends once with an eight-second abortable deadline including auth. Notification follows persistence, is awaited for up to four seconds and cannot turn a saved enquiry into failure. Late auth cannot trigger an append. Ambiguous appends are never automatically replayed; manual retry can duplicate a row. Logs contain generated correlation IDs, closed status/error classes and latency, without provider bodies or enquiry values.
- The typed/runtime-validated analytics adapter supports seven allowlisted events, fixed props and canonical paths. Only persisted 201 triggers conversion success. No sample event, auto pageview, raw query/referrer/UTM or field capture. Production runtime configuration requires every activation/processing flag; defaults, development and private previews remain disabled. Enabled transport is mocked, never sent to Plausible. Browser network IP would still be visible to the provider if later activated.
- Removed unused Vercel Analytics/Sonner and their obsolete CSP allowances after consumer checks. DENY anti-framing headers agree. Static inline bootstrap/JSON-LD remains allowed, with the security/cache tradeoff documented. The seven redirects now use a narrow Next proxy so local redirect responses carry the same headers; destinations, query strings and fragments remain covered.
- Env, deployment, website privacy facts, claims, ownership inputs, provisioning recipe and retention/deletion operations are documented in the [enquiry runbook](../operations/enquiries.md). Named response/incident/deletion owners and an alternate verified contact remain pending.
